# Ansible Inventory Parameters

## 1. Inventory Sources
Types of Inventory files
- **Static Inventory**: Defined in a file (for example, `inventory.yaml` file). You usually generate it manually.
- **Dynamic Inventory**: Generated by a script or plugin. In our case, our terraform provision module and **vsphere**: `terraform/vsphere` 

## 2. Host Parameters
- **Host Name**: The name or IP address that is assigned to the new host.
  - Example: `bootc-mke3-mngr1`
- **Variables**: Key-value pairs associated with the host.
  - Example: `ansible_connection` `ansible_ssh_private_key_file` `ansible_host`, `ansible_user`, `ansible_port`
  ```yaml
  hosts:
    # bootc-mke3-mngr1
    bootc-mke3-mngr1:
      ansible_connection: ssh
      ansible_ssh_private_key_file: /Users/bootc-mke3/Desktop/terraform/vsphere/ssh-keys/bootc-mke3.pem
      ansible_user: test
      ansible_host: 172.18.180.147

    # bootc-mke3-wrk1
    bootc-mke3-wrk1:
      ansible_connection: ssh
      ansible_ssh_private_key_file: /Users/bootc-mke3/Desktop/terraform/vsphere/ssh-keys/bootc-mke3.pem
      ansible_user: test
      ansible_host: 172.18.180.149
  ```

## 3. Group Parameters
- **Children Groups**: Groups nested in a group.
  - Example: `children`, `managers`
  ```yaml
  children:
    managers:
      hosts:
        bootc-mke3-mngr1:
    workers:
      hosts:
        bootc-mke3-wrk1:  
  ```

> [!IMPORTANT]
> `managers` and `workers` are not only example names. Every `bootc-mke3`
> playbook hardcodes them (`hosts: managers`, `hosts: workers`,
> `groups['managers'][0]` for the lead manager). If you rename these groups,
> the install fails and Ansible gives no warning.

## 4. Special Groups
- **all**: A built-in group that contains all hosts.
  ```yaml
    all:
        hosts:
            # bootc-mke3-mngr1
    ...
  ```
## 5. Variables 
- **vars**: A list of key-value pairs. They add variables to the ansible playbook, or overwrite variables that have the same key.
    - Example:
      ```yaml
      vars:
        mke_url: 172.18.180.147
      ```

> [!IMPORTANT]
> `mke_url` is required. The MKE install flags (`--san`), the client-bundle
> download tasks, and the SUC privilege grant use it. If you omit it, the
> install fails.

## 6. Inventory File Structure
Here is a full inventory file example (with dummy values):
- **YAML Format**: Modern format that uses the YAML syntax.
  - Example:
    ```yaml

        # bootc-mke3-wrk1
        bootc-mke3-wrk1:
          ansible_connection: ssh

      vars:

    ```

## FAQ
### How to generate ansible inventory from our Terraform provision modules
Our Terraform provision modules work with Ansible. It is thus easy to generate an inventory file.

  1. In the terraform directory of the applicable provider, run the command `terraform apply`. For example, for vsphere, use **terraform/vsphere/**.
  2. Run the output command for your platform:
     - AWS (`terraform/aws`): `terraform output -raw bootc_ansible_output`
     - vSphere (`terraform/vsphere`): `terraform output -raw ansible_inventory`
  3. Redirect the output and save it as a yaml file.
